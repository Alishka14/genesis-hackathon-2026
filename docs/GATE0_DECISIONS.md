# LedgerGym — Gate 0: решения для утверждения Tech Lead

**Статус:** PROPOSED, NOT APPROVED. Это набор инженерных умолчаний, **не** официальный текст FinTech-кейса. Приоритет обязательного кейса выше. **Код и тесты ещё не выполнялись.**

## Решения, которые можно принять единым пакетом

| ID | Вопрос | Предлагаемое решение | Основание / риск |
| --- | --- | --- | --- |
| DEC-01 | Поддерживаемые типы truth | `duplicate_invoice`, `payment_allocation`, `fx_conversion`, `period_cutoff` | Четыре официальные семейства; имена — наши внутренние |
| DEC-02 | Деньги и допуск | `amount_minor` целое; exact comparison после policy rounding; базовый tolerance 0 minor units. Для FX вычисляем expected_amount с Decimal и опубликованной policy | Убирает плавающие допуски; подтвердить по правилам кейса |
| DEC-03 | Currency | ISO 4217 uppercase, currency_scale в manifest/policy; не конвертировать валюту молча | Не принимать USD за KZT |
| DEC-04 | IDs | `affected_ids` канонизировать как отсортированное множество явно типизированных ID; от дубликатов ID внутри одного finding — schema error. ID не кодируют статус нарушения | Anti-shortcut; не считать разные сущности одним ID |
| DEC-05 | Evidence semantics | Для TP существует хотя бы один полный `allowed_evidence_set` как subset `evidence_ids`; лишние IDs не отменяют TP, но помечаются в EQT; invalid/unresolvable ID проверяется отдельным тестом | Соответствует «полный допустимый набор»; необходимо окончательно согласовать extra IDs |
| DEC-06 | Matching | Максимальное по мощности 1:1 двудольное сопоставление с стабильным tie-break | Нет зависимости от порядка findings |
| DEC-07 | Action wire | `{"type":"list_records","table":"ledger","cursor":null,"limit":20}`; аналогично `get_record/get_document/calculator/submit` | JSON-совместимо, не зависит от Python объектов |
| DEC-08 | Шаги | Любое действие, в т.ч. неверное, расходует 1 шаг; submit на шаге 100 разрешён, но на шаге 101 нет; `inspection_steps` = действия до submit (не включает сам submit) | Конкретизирует официальные 100 действий/стоимость; утвердить с командой |
| DEC-09 | Запуск | Python 3.11; offline CPU; один публичный запуск через `python -m scripts.verify_all` после реализации | Пример пути скрипта, не существующий файл |
| DEC-10 | Private boundary | Доверенный evaluator работает отдельно от кода агента, скрытые truth/provenance никогда не монтируются в agent workspace | Невозможно обойти простым чтением внутренних Python объектов |
| DEC-11 | Dataset versioning | schema_version + generator_version + config hash + seed; train/dev disjoint, закрытые эпизоды не включены в пакет агента | Reproducibility |
| DEC-12 | Диагностика | CAB/EQT/FAA только evaluator-side. Официальный F1/reward не меняются | Сохранение конкурсного контракта |
