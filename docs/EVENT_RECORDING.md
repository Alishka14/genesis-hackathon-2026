# Журнал событий и единая проверка

`evaluate_fixture_dataset` сохраняет новый `events.jsonl` рядом с неизменёнными `trajectories.jsonl` (`ledgergym-actions-v1`) и `summary.json`. Публичные схемы среды, финансовые данные, scorer и reward не меняются.

## Формат ledgergym-events-v1

Каждая строка — JSON с полями:

| Поле | Значение |
| --- | --- |
| event_format | `ledgergym-events-v1` |
| episode_id | публичный идентификатор эпизода |
| split, policy | метаданные baseline-экспорта, train/dev и название политики |
| step | -1 для reset; 0…N−1 для действий, как в actions-v1 |
| action | null при reset; переносимое действие для остальных шагов |
| observation | публичный ответ reset/step |
| reward | 0 при reset; фактическая награда среды при step |
| terminated, truncated | false при reset; фактические признаки при step |

`observation.next_cursor` после list_records заменяется на `{"from_step": N}`: ссылка на этот шаг вместо случайного токена текущей сессии. null сохраняется. Индексы действий не сдвигаются из-за reset. Это канонический формат артефакта, не изменение живого API. Повторно прочитанная страница может получить ссылку на новый шаг, даже если живой API вернул тот же токен. Для replay достаточно извлечь action из строк со step >= 0; конкретные токены восстанавливаются в новой сессии.

`public_events(actions, replay)` копирует только перечисленные поля и не изменяет исходные данные. Информация `info`, в том числе открытый `info.score`, не экспортируется. Reset info, private truth/provenance и seed не добавляются. В closed mode награда остаётся 0. Публичные документы сохраняются без фильтрации текста: функция опирается на allowlist среды и не является фильтром секретов для произвольного стороннего env.

В development-оценке журнал построен из фактических ответов проверочного replay трёх публичных baseline. Oracle имеет эталон и не экспортирует ни действия, ни события. Это журнал доверенного replay, не запись live stdout недоверенного процесса; Docker runner не изменён. Ошибочные действия, invalid submit, частичные траектории и truncation поддерживаются кодировщиком. Файловый baseline-экспорт содержит завершённые траектории.

При одинаковых входных данных/действиях и одинаковом исходе тайм-аута JSONL повторяется побайтово. Реальное срабатывание wall-clock timeout зависит от машины. Служебный отчёт verification.json содержит измеренное время и не обещает побайтового равенства.

## Проверка одной командой

`python -m ledgergym.verification NEW_DIR` либо установленный `ledgergym-verify NEW_DIR` выполняет:

1. pytest текущего пакета; отдельные log/JUnit-файлы, лимит 600 секунд, без автозагрузки внешних pytest-плагинов и наследованных PYTEST_ADDOPTS.
2. Создание 10 train + 10 dev company-эпизодов.
3. Четыре baseline, 60 replay с проверкой score; проверку полноты/порядка/метаданных событий, совпадения действий, reset и terminal. SHA-256 трёх отчётных файлов записываются в итог.

Каждый этап сохраняет статус и elapsed_seconds. При ошибке тестов генерация всё равно выполняется для диагностики; при ошибке генерации оценка NOT_RUN. Любая ошибка означает FAIL (код 1); любой skip без ошибок — PARTIAL (код 2); иначе PASS (код 0). Пустой набор, ошибка коллекции, отсутствие pytest/JUnit и тайм-аут не могут дать PASS. Если процесс принудительно прерван, оставшийся RUNNING не является успехом. Существующая папка не перезаписывается.

Из checkout по умолчанию используются соседние tests; из установленного wheel — tests в текущем каталоге поставки (если рядом с установленным пакетом нет tests). `--tests PATH` явно помечает test_scope=custom. Для полного отчёта использовать default и поставляемые тесты. Интерпретатор/pytest/Docker/image должны быть подготовлены заранее; команда не устанавливает и не загружает их. PASS не означает утверждение API, проверку официальных PDF, независимый аудит или готовность к сдаче. CPU/RAM peak пока не измеряются.
