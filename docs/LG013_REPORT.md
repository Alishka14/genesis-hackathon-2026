# LedgerGym lg-013 — результат этапа

Дата: 20.11.2026. Ветка: `agent/environment/lg-013`, база: `agent/contracts/lg-012` / `07eb61590919cbb5ade7b8e2b3ef86c828b9125a`. Этап: фабрика reset и воспроизведение действий на существующих малых генераторах.

## Поведение

Раньше reset игнорировал seed/config и сохранял прежний эпизод. Теперь `LedgerSandbox()` при reset создаёт новые публичные данные и соответствующий им оценщик. Явные seed/config воспроизводят эпизод; отсутствие seed выбирает новый случайный seed. Старые документы, курсоры и бюджет не переносятся. Неудачный reset запрещает дальнейшие действия до успешного сброса.

Для готового public episode сохранён конструктор `LedgerSandbox(public, evaluator)`. Он принимает только reset без параметров генерации; прежний молчаливый пропуск seed/config заменён ошибкой. CLI-пример переведён на фабрику.

Baseline сохраняет ссылки `cursor={"from_step":N}` на шаг, выдавший следующую страницу. Replay разрешает их через ответы нового запуска; проверяет таблицу, индекс и наличие следующей страницы, поддерживает повторное чтение. Исходный массив действий не меняется; episode_id и находки не переписываются. Частичная траектория разрешена, действия после завершения запрещены.

Формула reward и matcher не изменены. Никаких новых внешних runtime-зависимостей.

## Проверка

Окружение: macOS, CPython 3.12.14, pytest 8.4.2.

- До реализации factory: 16 новых проверок FAIL по отсутствующей фабрике/игнорированию seed.
- До реализации replay: 12 проверок FAIL по отсутствующему адаптеру. Дополнительный тест повторного использования одного Python-объекта действия воспроизвёл мутацию ссылки; исправлено копированием действия перед разрешением курсора.
- После реализации: все 29 новых проверок PASS.
- Полный `python -m pytest -q -rs`: **142 PASS, 6 SKIP**. Все шесть пропусков — `tests/test_isolated_runner.py`: точный образ Docker недоступен. Прямая проверка image inspect показала недоступный Docker daemon. Проверка изоляции в этой сессии не выполнена.
- `python -m ledgergym`: terminated=true, truncated=false, TP=1, FP=0, FN=0, reward=0.996.
- Созданы 20 малых учебных файловых эпизодов и отчёт четырёх baseline. Все **60 сохранённых не-oracle траекторий** повторены на загруженных эпизодах; итоговые score совпали с исходным запуском каждой политики.
- Пагинация отдельно проверена на тестовой таблице из 103 строк: 50/50/3, без пропусков и дубликатов, одинаковая оценка при новых курсорах. Эти строки проверяют API, а не финансовую корректность.

## Ограничения и следующий этап

Это этап API, не завершение P0. Генераторы по-прежнему создают малые учебные истории. Далее нужны согласованные финансовые истории на 200–2000 проводок и 20–200 документов, управление 0–12 дефектами, hard negatives и независимые проверки. Python 3.11 и защищённое закрытое выполнение здесь не проверены. Оригинальные PDF не получены; предварительные схемы и финансовые правила остаются предметом сверки.

Фабрика и replay выполняются только доверенным оркестратором. Python callback не является защитой от интроспекции недоверенного агента. В closed-режиме публичный результат скрывает reward/score, но OS-изоляция остаётся отдельной задачей. Для воспроизведения требуются исходные данные либо точные seed/config/version; один episode_id не удостоверяет содержание.

Распределением ролей и финальной сдачей занимается капитан; текущий пользователь — технический исполнитель. Merge, изменение доступа и конкурсная отправка на этом этапе не выполнялись.
