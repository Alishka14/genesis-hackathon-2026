# Каталог сценариев LedgerGym (актуальный срез для LG-040)

**Важно:** в проекте есть две разные финансовые модели и отдельный модуль
`payment_matching`. Функция, реализованная в одной модели, не обязательно
поддерживается остальными. Это ограниченная синтетическая среда для GENESIS,
а не система настоящего бухгалтерского учёта.

| --- | --- | --- | --- |

| Частичное/неверное распределение платежа | Реализовано | Реализовано (контролируемый split) | Публичная remittance и фактические references |

## Что именно делает LG-040

В `scenario=company` (v1) появился opt-in `foreign_currency` со
значениями `USD` (по умолчанию), `EUR`; `cutoff_timezone` принимает
`+03:00`, `+05:00` (по умолчанию), `+09:00`; `period_month` — `YYYY-MM`
для 2020–2039 годов (по умолчанию февраль 2026). Это расширение **не
поддерживает произвольные валютные пары**: базовая валюта KZT, обе валюты
имеют exponent 2, FX к исходной валюте KZT, округление HALF_EVEN. Фактические
котировки являются синтетическими и не должны использоваться для рынка.

Пример дополнительной проверки:

```python
from ledgergym.company_world import build_company
public, truth, private = build_company(42, {
    "postings": 320, "documents": 40,
    "cutoff_timezone": "+09:00",
    "foreign_currency": "EUR",
    "period_month": "2026-10",
    "compounds": {"fx_allocation": 1},
})
```

**Никакого автоматического переноса этих опций на модель v2 и конкурсные
20-эпизодные данные.** Исторический seed 2026, default profile и уже
проверенный публичный пакет должны остаться неизменными. Для внедрения новой
математики в `main` нужен отдельный полный P0 на SHA LG-040 и сравнение
с исходным результатом, включая offline wheel и Docker.

## Разделение ролей

- `payment_matching` — консервативный независимый внутренний модуль
  бухгалтерских allocations, не официальный scorer. Некоторые refund/reversal
  kinds в нём специально отклоняются, хотя модель v2 обрабатывает связанный
  `refund` по собственной схеме.
- `company_checks` и `company_checks_v2` — производственные независимые
  от private truth финансовые validators, но их правила делят предположения
  с детерминированным baseline.
- `independent_finance_audit` — второй кодовый путь, использующий Decimal
  и отдельное перечисление журнала/evidence. Это уменьшает риск общей ошибки
  реализации, но не заменяет экспертизу бухгалтера.
- `score` — официальный 1:1 evidence matcher и терминальный reward. LG-040
  **не меняет** формулу, лимиты или границу секретного оценщика.

Правила конкурса и ограничения: `docs/COMPETITION_RULES.md`,
