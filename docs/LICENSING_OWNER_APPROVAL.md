# LedgerGym: решение о лицензии и авторстве (требует подписи команды)

**Статус:** PENDING HUMAN APPROVAL. Этот документ **не является лицензией**
и не предоставляет третьим лицам права на исходный код. Не копируйте его
в `LICENSE` до письменного согласования всеми правообладателями.

## Что требует Genesis FinTech

Приложение FinTech (стр. 5) требует «исходники с лицензией и
зафиксированными зависимостями». Положение §08 разрешает библиотеки,
open-source и ИИ при раскрытии, без подмены авторства. Права на проекты
сохраняются у правообладателей (§09). Самого `THIRD_PARTY_NOTICES.md`
недостаточно, чтобы лицензировать **собственный** код.

## Варианты на выбор правообладателей

| Вариант | Преимущества | Обязательства / компромисс |
| --- | --- | --- |
| MIT | Простой, распространённый текст; разрешены использование и модификация | Нужны copyright notice и сохранение лицензии; третьи лица смогут коммерчески использовать код |
| Apache-2.0 | Явная патентная лицензия и NOTICE-практика | Больше юридического текста и требований по изменениям |
| Закрытая собственная лицензия для оценки | Можно выдать жюри строго ограниченное право review | Нужно проверить, допустима ли по условиям конкурса и достаточно ли документирована; открытая публикация не равна разрешению на использование |

**Рекомендация для утверждения командой:** MIT, если все фактические
правообладатели согласны открыть свои оригинальные изменения. Выбор
не делается моделью автоматически. При несовпадении авторов Git history,
состава официальной команды и реального вклада необходимо сначала
исправить карту авторства.

## Процедура, которую должен выполнить капитан

1. Зафиксировать официальное название команды и участников (2–4).
2. Для каждого участника подтвердить созданные им части, использованные
   внешние источники и разрешение на выбранную лицензию.
3. Сверить каждый внешне заимствованный компонент с
   `THIRD_PARTY_NOTICES.md`, `third_party_licenses/` и
   `docs/PROVENANCE_AND_AI_DISCLOSURE.md`.
4. Выбрать MIT / Apache-2.0 / другой правомерный вариант, заполнить
   атрибуцию и добавить утверждённый полный текст **LICENSE** в корень.
5. Зафиксировать согласие и SHA отдельного коммита. При добавлении LICENSE
   после исходного full P0 повторить gate на новом SHA.
6. Обеспечить доступ жюри по GitHub/Drive, проверить ссылки
   из чужого аккаунта или в приватном окне.

## Решение

- Выбранная лицензия: **НЕ УТВЕРЖДЕНА**
- Правообладатели и согласия: **НЕ ПОДТВЕРЖДЕНЫ**
- Дата утверждения: **НЕ УСТАНОВЛЕНА**
- SHA с добавленным LICENSE: **НЕ СУЩЕСТВУЕТ**

дополнительные LG-040 тесты, генераторные варианты, внутренний аудитор.
Техническая корректность и юридические подтверждения принадлежат
команде. Нельзя выдавать работу ИИ за только собственноручно написанную.
