# Каталог реализованных и запланированных сценариев

Соответствие мастер-плану v2 (§4–7), 21.11.2026. Статус относится к конкретной реализации, не к готовности всей конкурсной среды.

| Сценарий | Реализация | Проверка / ограничение |
| --- | --- | --- |
| F1 Duplicate invoice | company_world меняет service_ref второго invoice при сохранении двух отражений | company_checks, test_company_finance/world; равенства суммы недостаточно |
| F2 Missing/partial allocation | Изменяется invoice_refs, документальное назначение сохраняется | claim в KZT по правильному курсу; test_company_finance/world |
| F3 Wrong FX date/rate | Меняются rate_id и обе стороны payment journal | Корректная дата по +05:00; Decimal generator и рациональный checker |
| F4 Reporting period | Invoice journal переносится в неверный месяц | UTC/локальная граница проверена; affected invoice_id |
| C1 FX × allocation на границе | Оба дефекта затрагивают один частичный USD-платёж | Два самостоятельных основания, не сумма общего ущерба; это не распределение USD-платежа на KZT-инвойс |
| C2 Duplicate × allocation | Подмена service_ref и ссылка платежа на дублированное обязательство | Обе причины/доказательства проверяются отдельно |
| Clean company | 200–2000 проводок, 20–200 документов, 0 faults | Preflight до вмешательств, private provenance |
| Одинаковые законные суммы | Парные invoice с разными service_ref | Не являются дублями; разные публичные обязательства |
| Законная частичная оплата | Платёж меньше invoice, вся сумма платежа распределена | Поддерживается company и отдельным payment_matching |
| Несколько оплат одного invoice | Реализовано в payment_matching и ручных fixtures | Генератор пока не создаёт |
| Один платёж на несколько invoice | Реализовано в payment_matching и ручных fixtures | Генератор/policy/evidence пока не расширены |
| Переплата с остатком | Реализовано в payment_matching, остаток не теряется | Генератор/policy пока не расширены |
| Неоднозначные ссылки/конкуренция | AMBIGUOUS без автоматического распределения | Проверены перестановка, биективные ID и одинаковое UTC-время |
| Возврат/сторно | NOT IMPLEMENTED | Явный отказ; нельзя выдавать за корректный поддержанный сценарий |
| Межвалютное распределение | NOT IMPLEMENTED | FX-policy требуется отдельно; конвертация проводок уже существует |
| Корректировка договорных условий | NOT IMPLEMENTED | Нужна модель документа-основания |
| CAB causal flip + invariance pair | Отдельный парный артефакт NOT IMPLEMENTED | Тесты изменения fault switches и ID уже есть, но не заменяют заявленный CAB |

Размеры, суммы и ограничения company: `COMPANY_MODEL.md`. Сопоставление денег и truth разделено в `MATCHING_SPEC.md`. Новые сценарии нельзя просто включить в текущий public dataset без изменения policy и независимой проверки evidence.
