# lg-015 — Python 3.11, офлайн-поставка и проверка Docker

Дата: 21.11.2026. Ветка: `agent/integration/lg-015`, база — `agent/world/lg-014`, commit `c2e90e8d8efdbce1a73d18c2606242df7037c49b` (draft PR #14). Области №1 и №3 из сохранённого командного плана. Пользователь поручил продолжить техническую работу; персональные роли распределяет капитан.

Новая ссылка ChatGPT share из сообщения пользователя не прочитана: web/browser завершились тайм-аутом, прямой запрос вернул HTTP 503. За основу взяты ранее предоставленные master spec/start prompt и сохранённый `LEDGERGYM_TEAM_EXECUTION_PLAN.md`. Нельзя считать, что новая редакция плана по ссылке сверена.

## Реализовано

- Пакет `ledgergym==0.1.0.dev15`, Python >=3.11, без сторонних runtime-зависимостей; wheel/sdist и команды `ledgergym`, `ledgergym-company`, `ledgergym-evaluate`, `ledgergym-isolated`.
- Точные версии и SHA-256 восьми универсальных wheels для тестов/сборки. colorama сохранена для Windows-маркера pytest; Windows фактически не тестировалась.
- Сборщик офлайн-каталога в чистом временном дереве: проверяет сторонние wheels, включает исходники/тесты/документы/лицензии, создаёт общий SHA-256 manifest, не перезаписывает существующий каталог. Интерпретатор/Docker-образ не включены.
- Учёт сторонних компонентов и 38 файлов лицензий/уведомлений из оригинальных wheels, включая вложенные компоненты setuptools/wheel. Лицензия собственного кода остаётся решением правообладателей команды.
- Запущен локальный Docker Desktop/Engine, получен прежний закреплённый образ и впервые в текущем цикле повторены все контейнерные проверки. Добавлено чтение максимального company-эпизода: 2000 проводок + 200 документов, 46 чтений, submit на шаге 47, reward=0.908. Обнаружение доступности Docker в тестах теперь ограничено 10 секундами.

Скрипт сборки сначала выявил ошибку размещения sdist: setuptools меняет `sys.argv` при последовательных вызовах. Исправлено сохранением обоих путей до вызова backend и обязательной проверкой наличия исходного архива. Финальная поставка также проверяется пересборкой wheel из sdist без сети. Финансовый runtime, схемы данных и reward в этом PR не менялись.

Файлы фактического вывода передаются в `outputs/test-results/lg015-*`: установленный пакет, Linux без сети, Docker и проверки повреждённой поставки. Внешний `lg015-build-info.json` фиксирует commit и hashes выдаваемых архивов; эти значения не включаются в сам архив циклической ссылкой.

## Окружение и источники

- CPython 3.11.11: локальная управляемая сборка python-build-standalone, полученная uv 0.13.9; отдельный venv. Системный Python не заменялся.
- Сборка: pip 25.0.1, setuptools 80.9.0, wheel 0.45.1. Чистая установка macOS: pip 24.0 из venv; pytest 8.4.2 и зависимости из lock.
- Docker Engine 29.9.2, Linux arm64; образ `python:3.11.11-slim-bookworm@sha256:081075da77b2b55c23c088251026fb69a7b2bf92471e491ff5fd75c192fd38e5`. Образ не заменён на плавающий tag, не объявляется актуальным security baseline. Python/Docker/uv не входят в офлайн-архив.
- [PyPA: pyproject.toml](https://packaging.python.org/en/latest/guides/writing-pyproject-toml/), [uv: управляемые версии Python](https://docs.astral.sh/uv/concepts/python-versions/). Версии, hashes и лицензии пакетов взяты из фактически скачанных wheels; источники перечислены в `THIRD_PARTY_NOTICES.md`.

## Что остаётся

Эти тесты не доказывают защиту от всех атак на Docker/ядро. Нужны независимый security review и прогон на целевом окружении жюри, включая его архитектуру (amd64 здесь не проверена). Обычный in-process `LedgerSandbox` всё ещё не является границей для недоверенного кода. Docker Desktop оставлен запущенным для дальнейших локальных проверок; тестовые контейнеры удалены runner/`--rm`.

Нужны сверка оригинальных PDF, человеческий финансовый review, выбор лицензии кода команды, утверждение интерфейсов, затем разрешённые P1 causal/invariance пары и конкурсные материалы. Публичная публикация, merge, изменение доступа и подача не выполнялись.
