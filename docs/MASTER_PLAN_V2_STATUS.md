# Выполнение мастер-плана v2

## Актуализация: LG-029 P0 + Dashboard (21.11.2026)

Документ ниже представляет историческое состояние после первого этапа Payment–Invoice Matching. С тех пор последовательно добавлены PR №20, 23–28, 30–32. Все они ещё являются **draft PR**, `main` не обновлён.

- **Выполнено и подтверждено на родительских ветках:** четыре категории v1 ошибок, две compound-комбинации; v2 законные split/refund и отдельные контролируемые v2 duplicate/allocation faults; 10 train/10 dev; четыре baseline; 60 переносимых replay; шесть v2 причинных пар. Python 3.14 локальная full integration PASS, Docker **22/22 PASS**, офлайн wheel под Python 3.11.18 **9/9 PASS**, 45 installed-wheel tests PASS. Это **не** закрытая оценка организаторов.
- **Новое в PR №32, тестирование ещё требуется:** дополнительный полный recorder `trajectories_full.jsonl`, localhost-only read-only веб-панель для публичных данных, профилировщик CPU/RAM/wall-time и `docs/DESIGN_NOTE.md`. Никаких изменений официальной формулы reward.
- **P0 всё ещё заблокирован:** сверка деталей официального FinTech-кейса, human review финансовой и security-логики, GitHub Actions runners (issue #29), лицензия собственного кода и разрешения капитана на объединение PR, финальный просмотр и полноценный выпуск исходной версии, доступ жюри, видео/презентация и фактическая подача.
- **P1 и после конкурса:** полные EQT/FAA, широкие anti-shortcut/property-based shrinking исследования, более богатая поддержка overpayment/FX allocation, удалённый веб-хостинг и управляющий агентом frontend.

Подробные команды и границы: [P0 Dashboard handoff](verification/P0_DASHBOARD_2026-11-21.md) и [Design Note](DESIGN_NOTE.md). Отдельный экспорт полных событий не заменяет существующий формат `trajectories.jsonl` без согласования контракта.
