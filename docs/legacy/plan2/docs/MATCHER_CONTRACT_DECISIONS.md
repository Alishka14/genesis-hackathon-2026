# Открытые решения о форме findings

21.11.2026. Это конкретное сопоставление двух требований для review, не изменение схемы и не официальная сертификация.

В INTERFACES.md сейчас зафиксирован строгий submit: повторные ID, неизвестный тип и currency вне трёх заглавных ASCII-букв означают некорректную отправку. Диагностический p0-matcher-probe.py, добавленный с Role 3, ожидает иное. Сам диагностический скрипт не заменяет первичный опубликованный контракт. MASTER_PLAN_V2.md §9.1 требует канонизации именно по опубликованным правилам; их первоисточник для этих четырёх случаев пока не подтверждён.

| Вход | Действующий validate_submission | Ожидание диагностического скрипта |
| --- | --- | --- |
| Повтор в affected_ids | Весь submit некорректен | Считать список множеством; верная находка остаётся TP |
| Повтор в evidence_ids | Весь submit некорректен | Считать список множеством; полное доказательство остаётся TP |
| Неизвестный строковый type | Весь submit некорректен | Допустить структуру; находка даёт FP, эталон остаётся FN |
| currency="kzt" вместо "KZT" | Весь submit некорректен | Допустить структуру, но не менять регистр: FP/FN |

Это меняет поведение API: сейчас canonical scorer возвращает null-метрики и return=-1; альтернативный контракт возвращал бы обычные числовые метрики. Для одной верной и одной неизвестной находки при одном truth строгий контракт даёт -1, а альтернативный — TP=1, FP=1, FN=0, F1=2/3 и return=1/3 при нуле inspection steps. Closed reward по-прежнему должен оставаться нулевым.

Если будет выбран альтернативный контракт, минимальное согласованное изменение включает: разрешение повторов с set-семантикой после проверки исходных лимитов; отделение строкового формата type/currency от смыслового совпадения; сохранение точного сравнения регистра; обновление validate_submission, контрактных тестов и документации обоих интерфейсов. Пределы длины и число исходных элементов нельзя обходить повторением одинакового ID. Некорректные JSON-типы, отсутствующие поля и превышение лимитов должны оставаться invalid submit.

В текущем этапе эти четыре правила сохранены. Независимо от них исправлены доступность evidence ID и tie-break максимального matching; они не требуют смягчения формы findings. Результат диагностики теперь 5 PASS / 4 FAIL; четыре FAIL явно остаются открытыми.
