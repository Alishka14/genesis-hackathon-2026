# Финансовый verification gate: LG-F01…LG-F20

**Статус:** локальная матрица проверки LedgerGym, **не** официальные закрытые случаи жюри D01…D20. Закрытые финансовые эпизоды, их seed и ожидаемые исходы отсутствуют у команды; успешная локальная матрица **не** равнозначна автоматическому получению 25/25 баллов за данные.

Сквозной контракт: `build_company(seed, config)` → публичные таблицы + закрытый truth/provenance → независимый публичный `audit_company_public` → сравнение сигнатур и проверка доступных evidence → обратная реконструкция чистой финансовой истории.

## Положительные утверждения test suite

Для каждого случая независимо проверяются:

1. Точный размер `ledger` и число публичных документов; журнал в сумме сбалансирован.
2. Число/типы закрытых issues совпадают с планом, максимум 12.
3. `independent_audit` выводит по публичным фактам **те же signature tuple** (type, sorted affected IDs, amount, currency); вычисляет суммы через `Fraction`, не использует private truth.
4. На каждый truth issue имеется допустимый evidence set, содержащий минимально необходимую публичную цепочку и только адресуемые идентификаторы; длина ≤10.
5. История происхождения fault: обратный проход по `provenance.interventions` полностью восстанавливает детерминированную чистую компанию с теми же ID, документами и бухгалтерскими суммами.
6. Повторный вызов с seed/config выдаёт байтово одинаковый JSON.
7. Отдельно проверяется, что compound group содержит ровно две смысловые категории и общий payment ID; изменение корректной reference без обновления truth распознаётся как allocation fault.

## Воспроизведение

    python -m pytest -q tests/test_local_financial_matrix.py
    python -m pytest -q tests/test_independent_financial_audit.py tests/test_matcher_p0_regression.py
    python -m pytest -q -rs -p no:cacheprovider

Автоматический workflow выполняет тесты на Python 3.11 и 3.12 с актуальным pinned Docker образом. Ветку `main` до code review не менять.

## Важные ограничения, которые матрица не закрывает

- Фактические D01–D20 жюри: закрытые, **NOT_RUN**; нельзя переименовать LG-FXX в DXX и представить как официальный сертификат.
- `refund/reversal` и настоящие `split payments` в полном синтетическом company-world всё ещё не реализованы как полноценные корректные отвлекающие сценарии. Внутренний `payment_matching` умеет часть split-схем, но генератор компаний пока создаёт только один remittance invoice. Полная cross-currency allocation ещё отсутствует.
- Отдельный финансовый эксперт должен проверить учётную политику, допустимость FX conversion, сумму/даты (включая time zone), смысл начислений и устойчивость доказательств для hard negatives. Совпадение двух алгоритмов на одной упрощённой модели не доказывает верность реальным стандартам.
- Закрытая изоляция, официальный протокол агента, 4 baseline и запись траекторий оцениваются независимыми gate.
- В GitHub оставлен отдельный PR №21 с работой над recorder и unified offline command; здесь эта работа не дублируется.

## Исправление flaky subprocess teardown

Существующий `tests/test_role3_runtime.py::run_test_policy` использовал context-manager `Popen`, чей `__exit__` пытается закрыть буферизованный stdin после раннего выхода агента. На CI Python 3.11 это иногда приводило к `BrokenPipeError` вместо корректного `protocol_error`. В тестовом harness теперь `bufsize=0` и явная очистка pipes/process; сам transport/sandbox не менялся.

**Критерий готовности PR к review:** 20/20 параметризованных LG-F случаев, дополнительные regressions, полный CI на обеих версиях Python и реальные container checks PASS, отсутствие незадекларированных skip. Полная конкурсная приёмка всё ещё OPEN.
