# LedgerGym — ранний прототип

LedgerGym — проект синтетической RL-среды для финансового аудита. Репозиторий содержит **начальный прототип**, а не завершённое конкурсное решение. Текущий срез создаёт малый детерминированный пример, предоставляет ограниченные инструменты чтения и расчёта и оценивает находки по доказательствам и формуле проекта.

**Ограничение безопасности:** код среды и callback оценщика выполняются в одном процессе. Недоверенный агент может получить доступ к объектам и окружению Python, поэтому этот прототип не обеспечивает изоляцию hidden truth и не пригоден для закрытой оценки или запуска недоверенного кода. См. `docs/STATUS.md`.

## Проверка

Один локальный учебный пример без сети запускается командой `python -m ledgergym`. Это проверка связки, а не benchmark. Для запуска тестов нужен Python и pytest. В окружении, где pytest уже установлен:

```sh
python -m pytest -q
```

Среда исполнения прототипа использует только стандартную библиотеку Python. Установка pytest и его зависимостей может требовать сети; итоговая офлайн-сборка ещё не подготовлена. Проверенные версии и команды фиксируются в отчёте задачи, а не предполагаются для других окружений.

## Текущая реализация и ограничения

- `ledgergym/world.py`, `payment_world.py`, `fx_world.py`, `period_world.py`: небольшие самостоятельные генераторы четырёх типов ошибок и корректных контролей с предварительными финансовыми проверками. Это не полный конкурсный генератор.
- `ledgergym/episode_io.py`: сохранение шести публичных файлов и отдельных truth/provenance с воспроизводимым содержимым; разделение каталогов не защищает данные от недоверенного процесса.
- `ledgergym/env.py`: пять действий и локальные ограничения бюджета, без безопасной изоляции процессов.
- `ledgergym/score.py`: максимальное evidence-aware сопоставление 1:1, метрики, награда и проверка структуры submit.
- `docs/INTERFACES.md`: **неутверждённые** интерфейсные решения и нерешённые вопросы.
- `docs/STATUS.md`: оставшаяся работа и ограничения.

Полный масштабируемый генератор, минимум два compound-сценария, разнообразные hard negatives, независимый self-check, 20 конкурсных эпизодов, четыре baseline, безопасные trajectories и конкурсные материалы пока отсутствуют. Имеющиеся четыре типа — небольшие фиксированные примеры, не полноценное покрытие P0. Официальные PDF не были доступны в сеансе; контракт должен быть сверен с ними. Не интерпретируйте синтетические записи или результаты как профессиональное аудиторское заключение.

## Происхождение и ИИ

Код и документы текущего среза созданы при помощи OpenAI Codex по заданию капитана на основании приложенных мастер-спецификации и стартового промпта. Runtime-код использует стандартную библиотеку Python; для тестов применялся pytest. В текущем срезе сторонний код не копировался. Перед конкурсной сдачей команда должна независимо проверить вклад, условия лицензий и заполнить `docs/PROVENANCE_AND_AI_DISCLOSURE.md` по фактическому результату.

Создание/слияние и подача регулируются проектными правилами; merge, изменение доступа и отправка требуют явного подтверждения капитана.
