# Доступность доказательств и стабильный matcher

21.11.2026. Ветка `agent/matching/plan2-evidence` поверх draft PR #21, пакет 0.1.0.dev18. Выполнены два воспроизведённых исправления evaluator; остальные конфликтующие правила не скрыты.

## Исправления

1. `record_ids.addressable_ids` используется runtime, baseline, fixture replay, native restricted runner и canonical scorer. Record ID должен разрешаться однозначно внутри разрешённой таблицы; doc_id берутся из invoices/payments. Foreign keys сами по себе не дают права засчитать дополнительное evidence. Публичный reader и evaluator используют один алгоритм record_identifier, включая составной FX key. Посторонние таблицы исключены. Чтение документов с повторным doc_id сохраняет прежнее поведение первого совпадения.
2. Максимальное 1:1 сопоставление получает стабильный tie-break: issues в порядке issue_id, затем минимальный допустимый исходный индекс finding. Для каждого выбора проверяется, достижима ли оставшаяся максимальная мощность. Поэтому TP не зависит от жадного выбора. Назначение остаётся только у доверенного оценщика; публичный ответ score не расширен.

Для валидных уникальных строковых issue_id перестановка truth не меняет assignment. Для отсутствующих/нестроковых/повторных ID fallback использует позицию: это техническая совместимость, не утверждение схемы некорректного truth. Формула награды, денежный допуск, форма submit, лимиты и closed reward не изменены.

## Ограничения

PASS локальной команды не означает принятие всех конкурсных требований: четыре диагностических конфликта формы submit остаются открытыми. Не добавлены финансовые CAB-пары, расширенные hard negatives, refunds/FX allocation, независимый финансовый review или материалы сдачи. CPU/RAM peak не измерялся; Linux-лимиты не заменяют измерение. Схема duplicate doc_id требует отдельной валидации данных, она здесь не расширяется. Код и тесты подготовлены Codex на синтетических данных, без новых внешних библиотек. PR не слит, публикация и конкурсная отправка не выполнялись.
